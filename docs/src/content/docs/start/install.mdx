`tess` is a single static binary with the web app built in. It needs nothing else installed.

## Download a release

Each [release](https://github.com/arunksoman/tessera/releases/latest) has archives for Linux, macOS, and Windows on amd64 and arm64. The current release is **__TESS_VERSION__**.

<Tabs syncKey="os">
	<TabItem label="Linux">
		```sh
		curl -LO https://github.com/arunksoman/tessera/releases/download/v__TESS_VERSION__/tess___TESS_VERSION___linux_amd64.tar.gz
		tar -xzf tess___TESS_VERSION___linux_amd64.tar.gz
		sudo install tess___TESS_VERSION___linux_amd64/tess /usr/local/bin/
		tess version
		```
		Use `linux_arm64` on ARM machines.
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -LO https://github.com/arunksoman/tessera/releases/download/v__TESS_VERSION__/tess___TESS_VERSION___darwin_arm64.tar.gz
		tar -xzf tess___TESS_VERSION___darwin_arm64.tar.gz
		sudo install tess___TESS_VERSION___darwin_arm64/tess /usr/local/bin/
		tess version
		```
		Use `darwin_amd64` on Intel Macs.
	</TabItem>
	<TabItem label="Windows">
		Download `tess___TESS_VERSION___windows_amd64.zip` (or `windows_arm64`), extract it, and put the folder holding `tess.exe` on your `PATH`. In PowerShell:

		```powershell
		Invoke-WebRequest -OutFile tess.zip https://github.com/arunksoman/tessera/releases/download/v__TESS_VERSION__/tess___TESS_VERSION___windows_amd64.zip
		Expand-Archive tess.zip -DestinationPath $env:LOCALAPPDATA\tess
		$env:PATH += ";$env:LOCALAPPDATA\tess\tess___TESS_VERSION___windows_amd64"
		tess version
		```
	</TabItem>
</Tabs>

### Verify the download

Every release lists SHA-256 checksums, a CycloneDX SBOM, and a signed build provenance attestation, so you can check that an archive was built from this repository by its release workflow:

```sh
curl -LO https://github.com/arunksoman/tessera/releases/download/v__TESS_VERSION__/sha256sums.txt
sha256sum --check --ignore-missing sha256sums.txt
gh attestation verify tess___TESS_VERSION___linux_amd64.tar.gz --repo arunksoman/tessera
```

Releases are reproducible: the release job builds everything twice and fails if a single byte differs.

## Run in a container

`ghcr.io/arunksoman/tessera` runs `tess serve` on a distroless base as a non-root user, for amd64 and arm64. `:latest` and version tags follow releases, and `:edge` follows `main`. See [Run tess serve on a server](/guides/deploy/) for the full setup.

```sh
docker run --rm ghcr.io/arunksoman/tessera:__TESS_VERSION__ version
```

## Build from source

You need Go 1.26 and, for the web app, Node.js 22 or newer. On Windows, run `make` from Git Bash or let it find the shell that ships with Git.

```sh
git clone https://github.com/arunksoman/tessera
cd tessera
make            # builds the web app, then tess
./tess version
```

Without `make`, run `scripts/build-web.sh` and then `CGO_ENABLED=0 go build -o tess ./cmd/tess`. A `tess` built without the web app still works from the command line and the terminal; `tess serve` then shows a page saying the web app is missing.

<Aside type="note">
`tess` always builds with `CGO_ENABLED=0`, so it cross-compiles for any platform Go supports and has no C library dependencies.
</Aside>

## Where tess keeps its files

| What | Where |
|---|---|
| Profiles and settings | `config.toml` in the platform config directory: `~/.config/tessera` on Linux, `~/Library/Application Support/tessera` on macOS, `%AppData%\tessera` on Windows |
| Passwords | `secrets.json`, an encrypted vault in the same directory, keyed by a master key in the OS keychain |
| History and audit log | `state.db`, a SQLite database in the same directory |
| Installed plugins | `plugins/NAME/` in the same directory |

Set `TESSERA_CONFIG_DIR` to use another directory. The directory is created with mode `0700`. See [Secrets and configuration](/guides/secrets/) for hosts without a keychain.
