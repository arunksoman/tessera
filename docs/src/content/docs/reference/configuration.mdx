## Files

Everything tess keeps lives in one directory, the **config directory**. tess creates it, with mode `0700`, the first time it needs it. You never have to create the directory or any file in it yourself.

| OS | Default config directory |
|---|---|
| Linux | `$XDG_CONFIG_HOME/tessera`, usually `~/.config/tessera` |
| macOS | `~/Library/Application Support/tessera` |
| Windows | `%AppData%\tessera`, usually `C:\Users\<you>\AppData\Roaming\tessera` |

Set `TESSERA_CONFIG_DIR` to use another directory. It moves **everything**: `config.toml`, the vault, history, and installed plugins. Use it to keep separate setups, for example one per project or one for tests:

```sh
export TESSERA_CONFIG_DIR=$PWD/.tess
tess profile add local --tile sqlite --set path=dev.db --set create=true
tess tui local
```

<FileTree>
- tessera/ the config directory
  - config.toml settings, plugin settings, and profiles
  - secrets.json encrypted passwords
  - secrets.salt only when TESSERA_PASSPHRASE is used
  - state.db history and audit log
  - plugins/
    - duckdb/ one folder per installed plugin
      - tess-duckdb-linux-amd64 the plugin binary
      - plugin.json install record with the pinned SHA-256
</FileTree>

| File | Contents |
|---|---|
| `config.toml` | Settings, plugin settings, and profiles. No secrets. |
| `secrets.json` | Passwords, encrypted with AES-256-GCM |
| `secrets.salt` | The salt for `TESSERA_PASSPHRASE`, when used |
| `state.db` | History and the audit log, in SQLite |
| `plugins/NAME/` | An installed plugin's binary and its `plugin.json` record with the pinned hash |

## config.toml

You do not need to create `config.toml`. tess writes it the first time you add a profile or change a setting, and works without one until then. To set something by hand, such as `allow_in_server`, open the existing file in the config directory and edit it; create it there only if it does not exist yet.

<Aside type="caution" title="tess rewrites the whole file">
Whenever tess saves a profile or a setting, it writes `config.toml` again from what it understood. **Comments are dropped, and so are keys tess does not know, including misspelled ones**: `allow_in_sever = true` is ignored without a warning, and gone after the next save. After a hand edit, check that tess sees it, for example with `tess profile list`.
</Aside>

- tess writes the file atomically, to `config.toml.tmp` and then renamed into place, with mode `0600`, so a crash never leaves it half written.
- A TOML syntax error makes every command that reads the file fail with `config.toml:` and the parser's message, until you fix it.
- Profile names, as in `[profiles.NAME]`, use letters, digits, `_`, `.`, and `-`.

```toml
theme = "dark"          # TUI theme: "light", "dark", or empty to follow the terminal
history_keep = 10000    # newest history entries kept; 0 means the default, 10,000

[plugins]
allow_in_server = false                                         # let tess serve load plugins
indexes = ["https://example.com/tessera-plugins/index.json"]   # name lookups for install

[plugins.sources]
elasticsearch = "github:acme/tessera-elasticsearch@v0.2.0"

[plugins.trusted_keys]
acme = "BASE64-PUBLIC-KEY"

[profiles.app]
tile = "postgres"
env = "production"      # confirmations for every write
color = "red"           # web app colour: red, orange, yellow, green, cyan, blue, purple, pink
read_only = false
no_history = false

[profiles.app.values]   # the tile's connection form fields
host = "db.example.com"
port = "5432"
user = "app"
database = "app"
sslmode = "verify-full"
```

Field names under `values` that look like secrets (containing `pass`, `pwd`, `secret`, or `token`) are refused. Passwords go in the vault through `--password-stdin` or a form's password field.

## Environment variables

| Variable | Meaning |
|---|---|
| `TESSERA_CONFIG_DIR` | Use this directory instead of the default |
| `TESSERA_MASTER_KEY_FILE` | A file holding exactly 32 bytes, used as the vault's master key instead of the OS keychain |
| `TESSERA_PASSPHRASE` | A passphrase from which the master key is derived with Argon2id, instead of the OS keychain |
| `NO_COLOR` | Turn off colour in the TUI |

When both are set, `TESSERA_MASTER_KEY_FILE` wins over `TESSERA_PASSPHRASE`. See [Passwords and secrets](/guides/secrets/).
